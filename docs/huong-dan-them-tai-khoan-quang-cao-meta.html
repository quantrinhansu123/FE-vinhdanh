Hướng dẫn thêm tài khoản quảng cáo Meta

Dành cho dev tiếp quản hệ thống MAS / FE-vinhdanh: đưa một tài khoản quảng cáo (TKQC) mới vào trang Meta Ads, báo cáo detail_reports và cron đồng bộ.
Cập nhật 18/11/2026 · Áp dụng từ commit 792c948 (PR #5) trên main · Tài liệu liên quan: docs/meta-api-handover.vi.md

1. Tóm tắt nhanh

Hệ thống không có nút "Kết nối Facebook". Mọi dữ liệu Meta được đọc bằng một token chung của một System User, trên một danh sách TKQC cố định trong biến môi trường. Muốn thêm một tài khoản thì phải làm đủ 3 việc. Thiếu một việc là tài khoản sẽ không hiện:

  1. Cấp quyền trên Meta: gán System User Conversions API System User vào TKQC với quyền Xem hiệu quả.
  2. Khai báo ID: thêm Ad Account ID vào META_AD_ACCOUNT_IDS trên Vercel Production (và .env local, .env.example).
  3. Redeploy trên Vercel. Biến môi trường mới chỉ áp dụng cho các lần deploy sau.
TKQC trên Meta→ gán quyền → System User (token ads_read)→ META_AD_ACCOUNT_IDS trên Vercel→ redeploy → /api/meta-project-qc→ Trang Meta Ads · detail_reports · cron 15 phút

2. Các bước thêm tài khoản

1

Lấy Ad Account ID của tài khoản mới

Cách nhanh nhất: business.facebook.com → Cài đặt → Tài khoản → Tài khoản quảng cáo, bấm vào tên tài khoản. ID hiện ngay dưới tên, dạng số 15–17 chữ số, ví dụ 2895622560812930.

Hoặc trong Ads Manager: bấm ô chọn tài khoản ở góc trên bên trái → chọn BM Sofonio Fenda → danh sách hiện "ID tài khoản quảng cáo: …" (danh sách dài thì bấm "Xem thêm").

Lưu ýChỉ dùng Ad Account ID. Không dùng Business ID, Page ID, Facebook User ID hay mã TKQC nội bộ CRM. Không thêm tiền tố act_ vào env (code tự bỏ nếu có, nhưng nên giữ đồng nhất).
2

Gán System User vào tài khoản với quyền "Xem hiệu quả"

Cách A, khi thêm nhiều tài khoản cùng lúc:

  1. Cài đặt → Người dùng → Người dùng hệ thống → chọn Conversions API System User.
  2. Bấm nút ⋯ cạnh "Tạo mã / Thu hồi mã" → Chỉ định tài sản.
  3. Cột trái chọn Tài khoản quảng cáo. Tick các tài khoản cần thêm. Tài khoản đã gán sẵn có nhãn "Đã chỉ định".
  4. Cột phải bật Xem hiệu quả (thuộc "Quyền truy cập một phần"). Không bật "Quản lý chiến dịch" hay "Quản lý tài khoản quảng cáo": hệ thống chỉ đọc.
  5. Bấm Chỉ định tài sản, đợi thông báo "Đã chỉ định tài sản".

Cách B, khi thêm một tài khoản: Cài đặt → Tài khoản quảng cáo → chọn tài khoản → Chỉ định người → tìm "Conversions" → tick Conversions API System User (Người dùng hệ thống) → bật Xem hiệu quả → Chỉ định.

Tài khoản không nằm trong danh sách để chọn?Nghĩa là tài khoản đó chưa được chia sẻ cho BM Sofonio Fenda. Phải nhờ BM sở hữu (cột "… sở hữu tài sản này") chia sẻ quyền truy cập cho Sofonio Fenda trước, rồi mới gán được.
3

Kiểm tra token đã đọc được tài khoản mới

Chạy ở thư mục gốc repo. Script chỉ đọc, không in token ra màn hình. Truyền ID mới ở tham số thứ hai để kiểm tra trước khi thêm vào env:

node scripts/checkMetaAccounts.mjs .env 2895622560812930

Kết quả đạt, ví dụ:

token valid: true | type: SYSTEM_USER | app: fabico
scopes: ads_read, public_profile
  OK   1403117645112746 | FBC - A1 | ACTIVE | VND
  OK   2895622560812930 (new) | FBC - C4 | ACTIVE | VND
readable: 38/38
Thấy dòng FAIL với "(#200) Ad account owner has NOT grant ads_management or ads_read permission"Bước 2 chưa xong hoặc gán nhầm user. Quay lại bước 2. Không tạo token mới: token hiện tại đã đủ scope, chỉ thiếu quyền trên tài sản.

Script cần Node 18+ (dùng fetch có sẵn). Exit code 1 nếu có tài khoản FAIL, nên có thể dùng trong CI.

4

Thêm ID vào biến môi trường local và .env.example

Nối ID mới vào cuối META_AD_ACCOUNT_IDS, phân cách bằng dấu phẩy, không dấu cách, giữ nguyên các ID cũ:

META_AD_ACCOUNT_IDS=1403117645112746,4138174149811846,...,4041009812777827,<ID_MOI>
  • .env (hoặc .env.local): cấu hình local, không commit (đã có trong .gitignore).
  • .env.example: cập nhật cùng danh sách rồi commit, để người sau biết danh sách hiện hành. Chỉ chứa ID, không bao giờ chứa token.
  • Chạy lại node scripts/checkMetaAccounts.mjs .env: phải ra readable: N/N.
Lưu ý về file .envFile .env trong repo dùng xuống dòng kiểu Windows (CRLF). Không dùng source .env trong bash vì ký tự \r sẽ dính vào giá trị và làm request lỗi. Dùng script ở bước 3, hoặc thư viện dotenv như code server.
5

Cập nhật Vercel Production và Redeploy

  1. vercel.com → project fe-vinhdanh → Settings → Environment Variables.
  2. Sửa META_AD_ACCOUNT_IDS, dán đúng giá trị như trong .env. Đảm bảo có tick môi trường Production.
  3. Deployments → bản Production mới nhất → ⋯ → Redeploy.
Lỗi hay gặp nhấtSửa biến mà quên Redeploy, hoặc sửa nhầm project. Tài khoản GitHub này nối với 3 project Vercel: fe-vinhdanh, fe-vinhdanh-9utb, vinhdanhfabico. Domain fe-vinhdanh.vercel.app thuộc project fe-vinhdanh. Ngày 18/11/2026 production vẫn chỉ đọc 18 tài khoản dù đã "sửa trên Vercel", chính vì lý do này.
6

Kiểm tra trên production

  1. Mở https://fe-vinhdanh.vercel.app/crm-admin/meta-ads, xác nhận tài khoản Admin CRM nếu trang hỏi. Phiên này hết hạn sau 1 giờ.
  2. Chọn khoảng ngày có chi tiêu → Lấy từ API Meta.
  3. Dòng tổng phải ghi "Đã tải: N tài khoản", với N đúng bằng số ID trong META_AD_ACCOUNT_IDS.
  4. Không có dòng cảnh báo vàng "Token Meta chưa có quyền đọc … tài khoản".
  5. Tài khoản mới có chi tiêu thì phải xuất hiện trong bảng, cột "Tên tài khoản".

Chỉ khi số liệu đọc đúng mới bấm Đồng bộ Meta → detail_reports. Cron /api/cron-marketing-sync chạy mỗi 15 phút sẽ tự đồng bộ hôm nay và 3 ngày trước.

XongTài khoản mới đã có trong trang Meta Ads, báo cáo nhân viên và cron.

3. Hệ thống phản ứng thế nào khi một tài khoản mất quyền

Từ PR #5 (18/11/2026), server/metaProjectQc.ts xử lý lỗi theo từng tài khoản:

Tình huốngHành vi
Một vài TKQC báo lỗi quyền (Meta code 10, 200, hoặc 100/subcode 33)Bỏ qua các tài khoản đó, vẫn trả dữ liệu các tài khoản còn lại. API trả thêm failedAccounts. Trang Meta Ads hiện cảnh báo vàng kèm danh sách ID.
Tất cả TKQC đều lỗi quyềnRequest lỗi với meta_permission_denied.
Token sai hoặc bị thu hồi (code 190), rate limit, mất kết nốiCả request lỗi, vì các lỗi này ảnh hưởng mọi tài khoản.
Bấm Đồng bộ Meta → detail_reports hoặc cron chạy khi có failedAccountsTừ chối đồng bộ với lỗi meta_accounts_incomplete. Lý do: RPC replace_meta_project_qc_insights ghi đè toàn bộ khoảng ngày, nếu đồng bộ với dữ liệu thiếu thì số liệu đã lưu của tài khoản lỗi sẽ bị xoá.
Hệ quảMột tài khoản mất quyền sẽ chặn cron đồng bộ báo cáo, dù trang Meta Ads vẫn xem được. Thấy cảnh báo vàng thì cấp lại quyền (bước 2), hoặc gỡ ID khỏi danh sách (mục 5).

5. Gỡ một tài khoản khỏi hệ thống

  1. Xoá ID khỏi META_AD_ACCOUNT_IDS trên Vercel, Redeploy, và cập nhật .env, .env.example.
  2. Sau đó mới gỡ quyền System User trên Meta, nếu cần.
Cẩn thận dữ liệu cũLần đồng bộ tiếp theo (kể cả cron) sẽ ghi đè snapshot của khoảng ngày được chạy lại. Số liệu của tài khoản vừa gỡ trong các ngày đó sẽ mất khỏi meta_project_qc_insights và detail_reports. Cron chạy lại hôm nay và 3 ngày trước. Nếu cần giữ lịch sử của tài khoản bị gỡ, hãy sao lưu trước khi đổi env.

6. Checklist

  • Đã có Ad Account ID dạng số.
  • Đã gán Conversions API System User với quyền "Xem hiệu quả".
  • node scripts/checkMetaAccounts.mjs .env <ID> báo OK.
  • Đã cập nhật .env và .env.example (giữ ID cũ). readable: N/N.
  • Đã sửa META_AD_ACCOUNT_IDS trên Vercel project fe-vinhdanh, môi trường Production.
  • Đã Redeploy.
  • Trang /crm-admin/meta-ads hiện "Đã tải: N tài khoản", không có cảnh báo vàng.
  • Đã commit .env.example qua PR.
